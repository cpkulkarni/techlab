# 🎛️ Pipeline & Workflow Builder

The **Pipeline & Workflow Builder** enables developers and teams to visually design, order, configure, and execute multi-stage AI agent automation workflows.

---

## 🏗️ 1. Pipeline Concepts & Workflow Structure

A **Pipeline** is a directed sequence of automated steps designed to accomplish complex engineering goals (such as feature development, automated regression testing, or documentation synchronization).

```
+---------------------------------------------------------------------------------------------------+
| 🔀 FEATURE AUTOMATION PIPELINE                                                                     |
+---------------------------------------------------------------------------------------------------+
|                                                                                                   |
|  [ Step 1: RESEARCH ] ----> [ Step 2: CODE ] ----> [ 🛡️ APPROVAL ] ----> [ Step 3: TEST ]        |
|  Status: SUCCESS            Status: SUCCESS         Status: APPROVED      Status: IN PROGRESS     |
|                                                                                                   |
+---------------------------------------------------------------------------------------------------+
```

---

## 🧩 2. Supported Step Types & Configuration Parameters

| Step Type | Execution Agent / Tool | Inputs & Configuration | Output Artifact |
| :--- | :--- | :--- | :--- |
| **`RESEARCH`** | Technical Researcher Agent | Query prompt, domain filters, search entry count. | Markdown Research Brief in `/docs/research/` |
| **`CODE`** | Code Synthesis Coder Agent | Target file path, feature specification, prompt context. | Updated source file on disk |
| **`TEST`** | QA Engineer Agent | Target module path, assertion rules. | TypeScript test file (`.test.ts`) & test run report |
| **`DOCS`** | System Documentation Specialist | Target documentation file path, feature scope. | Updated Markdown spec in `/docs/` |
| **`COMMAND`** | System Shell Runner | Command string (e.g. `npm run lint`, `npm run build`). | Terminal execution log & exit code |

## 🎛️ 3. Interactive Workflow Builder Controls

### 3.1 Step Creation & Drag-and-Drop Sequencing
- Click **+ Add Step** in the Pipeline Builder toolbar.
- Select the Step Type (`RESEARCH`, `CODE`, `TEST`, `DOCS`, `COMMAND`).
- Drag step cards by their grab handle to reorder the execution sequence.
- Toggle steps between Enabled and Disabled states.

### 3.2 Human Approval Checkpoints (`requireApproval: true`)
When **Require Human Approval** is checked on a step:
1. Workflow execution proceeds automatically until it encounters the approval checkpoint.
2. The pipeline transitions to **PAUSED (`PAUSED_AWAITING_APPROVAL`)**.
3. The UI highlights the step card with a yellow border and displays an **Approve & Continue** / **Reject Step** dialog.
4. Intermediate outputs generated by prior steps are displayed for human review.

---

## 🚀 4. Workflow Execution & Real-Time Monitoring

When you click **Execute Pipeline**:
1. The client sends a request to POST `/api/workflow/execute`.
2. The backend boots a Server-Sent Events (SSE) stream (`GET /api/workflow/stream/:executionId`).
3. Active status badges update dynamically on each step card:
   - 🟡 **`PENDING`**: Step queued in workflow.
   - 🔵 **`IN_PROGRESS`**: Step currently executing via AI agent.
   - 🟢 **`SUCCESS`**: Step completed successfully with output.
   - 🔴 **`FAILED`**: Step failed with error stack trace.
   - 🟠 **`PAUSED`**: Paused awaiting human approval.

## 📊 5. Pre-configured Workflow Templates

The Pipeline Builder includes ready-to-run built-in templates:

1. **Full Feature Pipeline**:
   - `RESEARCH`: Analyze feature requirements & API contracts.
   - `CODE`: Implement feature components and Express routes.
   - `TEST`: Generate and execute unit test suites.
   - `DOCS`: Update system documentation.
2. **Documentation Sync Pipeline**:
   - `DOCS`: Scan codebase and update `/docs/01_USER_GUIDE_APPLICATION.md`.
3. **Regression Test Suite Pipeline**:
   - `COMMAND`: Run `npm run lint`.
   - `TEST`: Execute all unit tests in `tests/`.
